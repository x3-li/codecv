# Gen HTML PPT

モダンブラウザで直接実行できる、HTML ベースの完全なプレゼンテーションを作成します。

## ワークフロー

1. ユーザーのトピック、メモ、想定聴衆、言語、スライド枚数、発表時間、デザインの好みを読み取ります。
2. 不足している要件がスライド全体に大きく影響する場合のみ確認します。それ以外は合理的に仮定し、`[please add data]`、`[please insert screenshot]`、`[please confirm date range]` のような見えるプレースホルダーを使用します。
3. スライドを設計する前に、元の内容を分析します。
   - 物語の流れを整理します。
   - 重複または不要な情報を削除します。
   - 長い文章を、プレゼンテーション向けの短い表現に変換します。
   - 各スライドから明確な結論を 1 つ抽出します。
   - データ、顧客名、調査結果、引用元を捏造しません。
   - 元資料に明確な数値がない場合は、定性的な表現を使用します。
4. タイトル、アジェンダ、本文、まとめ、締めまたは Q&A スライドを含む、適切で完全なスライド構成を設計します。
5. コーディング前に、統一されたビジュアルシステムを定義します。レイアウトパターン、色、タイポグラフィ、余白、コンポーネント、強調ルールを含めます。
6. ユーザーが別の場所を指定しない限り、現在のプロジェクトディレクトリ内に実ファイルを作成します。
7. 文字のはみ出し、配置、可読性、ナビゲーション、印刷 / PDF 出力の挙動を確認します。

## 標準的なスライド構成

この構成を機械的に当てはめるのではなく、トピックに合わせて調整します。

1. 表紙
2. 背景または課題提起
3. 目的
4. 中核内容の概要
5. 主要セクション 1
6. 主要セクション 2
7. 主要セクション 3
8. データ、プロセス、ケーススタディ、またはアーキテクチャ
9. リスク、問題点、または注意事項
10. 次のステップ
11. まとめ
12. Q&A またはクロージング

## スライド内容のルール

- 1 枚のスライドでは、主要なアイデアを 1 つだけ表現します。
- 各スライドのタイトルは、そのスライドの結論が直接伝わるようにします。
- スライド上に記事のような長い段落を置くことは避けます。
- 本文は 1 スライドあたりおおよそ 3〜6 点に収めます。
- 各ポイントはできるだけ短くし、できれば 2 行以内にします。
- 文字サイズ、太さ、余白、レイアウト、シンプルな図形によって重要情報を強調します。
- 過度な装飾や視覚的な clutter を避けます。
- スライド間の明確なストーリー上のつながりを維持します。

## 推奨レイアウトパターン

内容に合うレイアウトを選択します。

- 大きなタイトルと中核結論
- 左にテキスト、右にビジュアル
- 左にビジュアル、右にテキスト
- 3 カラムのカード
- タイムライン
- プロセス図
- 比較グリッド
- アーキテクチャ図またはフロー図

## 技術要件

完全に実行可能なフロントエンドを作成します。原則として、以下のようにファイルを分けます。

```text
index.html
style.css
script.js
README.md
```

非常に小さなスライドデッキであれば、CSS や JavaScript を `index.html` にインライン化しても構いません。ただし最終成果物は、HTML ファイルを直接開くだけで実行できる必要があります。

実装するもの:

- ブラウザ全画面のプレゼンテーションレイアウト。
- 一度に表示されるスライドは 1 枚のみ。
- マウスクリックによる前へ / 次への操作。
- キーボードナビゲーション。
- 現在ページ番号と総スライド数。
- プレゼンテーション進捗バー。
- Chrome、Edge、Safari などのモダンブラウザ対応。
- ブラウザからデッキ全体を PDF にエクスポートできる印刷スタイル。

## デザインガイダンス

- ユーザーが求めるスタイルと聴衆に合わせます。技術共有では、強い階層構造と明確な図解を備えた、洗練されつつ控えめなインターフェースを優先します。
- 表示されるスライドテキストには、ユーザーが指定したプレゼンテーション言語を使用します。
- デスクトップサイズとモバイルサイズのどちらでも、テキストがコンテナ内に収まるようにします。
- レイアウトのずれを避けるため、安定したスライド寸法とレスポンシブな制約を使用します。
- 各ページに装飾要素を詰め込みすぎないようにします。

## 完了時の報告

スライドデッキを作成または修正した後、以下を報告します。

- 生成されたファイル構成。
- プレゼンテーションを開く、または実行する方法。
- 仮定、プレースホルダー、または検証上の制約。
