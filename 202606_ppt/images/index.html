Background

背景

背景

本番室はインターネットに接続できません。それでも作業判断は止められません。

保守、障害対応、リリース作業では、コマンドの意味、ログの手掛かり、設定差分、作業手順を確認する場面が多くあります。これまでは経験、文書、人による確認に頼っていました。そこで、安全境界の内側にローカル AI アシスタントを用意します。

現場の課題困った時に外部検索やオンライン AI を使えない
安全前提本番情報は内網から出さず、推論はローカルで完結
目指す機能コマンド説明、ログ分析、手順確認、初動調査
構成方針ブラウザ入口 + 負荷分散 + 2 台の GPU 推論ノード
ポイント：本番室の隔離ルールを守りながら、AI 支援を作業現場へ持ち込む2 / 9

約 260 億

正式名称：Gemma-4-26B-A4B-NVFP4
読み方はシンプルです。Gemma 第 4 世代、総規模 26B、推論時に約 4B を有効化し、NVFP4 量子化を使うモデルです。

名前を暗記するより、モデルの世代、規模、有効化されるパラメータ、量子化形式を読み取ることが大切です4 / 9

Inference Engine

vLLM

推論

vLLM は本プロジェクトのモデル推論サービスです。

Gemma-4-26B-A4B-NVFP4 をロードし、GPU 推論を管理し、API リクエストを受け取り、生成結果を上位サービスへ返します。同じ領域のツールとしては Ollama、TGI、llama.cpp server などがあります。

Load

モデルをロード

ローカルのモデル重みを GPU / VRAM に載せ、アクセス可能な推論サービスとして起動します。

Serve

API を提供

互換性のある呼び出し口を公開し、上位の LiteLLM からモデル API のように利用できます。

Speed

スループット向上

並列推論を意識したスケジューリングにより、複数人が同時に使う場面に向いています。

GPU

GPU を活用

大規模モデルの計算を DGX Spark の GPU 上で実行します。

Local

ローカル実行

モデルとデータを本番室内網に留め、隔離環境の要件を満たします。

Similar

類似ツール

Ollama は使いやすさ寄り、vLLM は高性能なサービス化推論寄りです。

vLLM は「モデルを動かすエンジン」と考えると分かりやすいです5 / 9

Proxy / Load Balancer

litellm

中継

本プロジェクトでは主に 2 つの機能を使います

LiteLLM には多くの機能がありますが、ここでは OpenAI-compatible proxy と、2 つの vLLM backend に対する load balancing に絞って利用します。

routing_strategy: simple-shuffle
Proxy

API 入口の統一

OpenWebUI は LiteLLM に接続するだけで、背後に何台の vLLM があるかを意識しません。

LB

リクエスト分散

利用者のリクエストを DGX Spark #1 と #2 に分散し、1 台への集中を避けます。

Model Alias

モデル名管理

バックエンドのモデルを、利用者に分かりやすい名前として公開できます。

Routing

ルーティング戦略

simple-shuffle はシンプルで分かりやすく、現在の 2 ノード構成に適しています。

Future

今後の拡張

将来的にはレート制限、ログ、認証、fallback、利用統計なども接続できます。

Boundary

役割の分離

LiteLLM は推論を行わず、リクエストを正しい推論サービスへ届けます。

LiteLLM は「リクエストの交通整理役」と考えると分かりやすいです6 / 9

Chat Interface

openwebui

画面

OpenWebUI は利用者が実際に触る入口です。

下位のモデル機能を ChatGPT のような利用体験として提供します。作業者は API を直接扱う必要がなく、内部 URL を開き、モデルを選び、質問を入力するだけです。

話

チャット対話

コマンド説明、ログ分析、手順確認を行うメイン作業領域です。

模

モデル選択

Gemma-4-26B-A4B-NVFP4 などの利用可能モデルを表示します。

人

ユーザーと権限

実際の安全要件に合わせて、アカウント、アクセス範囲、ロールを管理できます。

知

ナレッジ / RAG

今後、内部手順書、FAQ、障害資料を接続し、回答の現場適合度を高められます。

文

ファイルと履歴

対話履歴やファイル入力を扱えます。データ保存方針との整合が必要です。

管

管理設定

LiteLLM への接続、モデル表示、システムプロンプト、利用ポリシーを設定します。

OpenWebUI は「作業者が AI と対話する窓口」と考えると分かりやすいです7 / 9
