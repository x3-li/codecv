Background

従来のPPT作成は、内容よりも整形に時間を使いやすい

発表資料の価値は「伝える内容」にあるが、実際はレイアウト調整が作業時間を圧迫しやすい。

  • 構成、文章、デザインを同時に考える必要がある
  • ページごとの余白や見出し位置を手作業で整える
  • 修正依頼のたびに全体のバランスを見直す
  • 短時間の共有資料ほど、作成負荷が目立つ

Goal

目標は「1つのPrompt」から発表できる初稿を作ること

1

AIに目的・観客・内容・ページ数・デザインを渡し、ブラウザで動くPPTを生成する。

完成品を一発で固定するのではなく、初稿を早く作り、人が確認して改善する流れにする。

Why Web PPT

Web版PPTは、AI生成と相性がよい実用フォーマット

01

すぐ開ける

HTMLファイルをブラウザで開くだけで、発表画面として利用できる。

02

修正しやすい

文章、色、余白、動作をコードとしてAIに再修正させやすい。

03

配布しやすい

ブラウザ印刷でPDF化でき、共有資料にも変換しやすい。

Tools

おすすめは、ファイルを直接作れるAI Agent系ツール

Codex

ローカルのプロジェクトに直接ファイルを作成・修正できる。HTML PPT作成と相性がよい。

Claude Code

同じくAgent型の開発支援ツールとして利用可能。

Kimi Code

国内利用環境での代替候補として検討できる。

選定ポイント: ファイル編集、プレビュー確認、修正指示、再生成が一連の流れでできること。

Prompt Design

Promptは「何を作るか」より「どう使うか」まで書く

Topic

テーマ

発表の主題と、伝えたい中心メッセージ。

Audience

観客

部門内、技術者向け、初心者向けなどの前提。

Content

素材

箇条書き、メモ、既存資料、入れたいキーワード。

Output

成果物

ページ数、言語、ファイル構成、操作機能。

Style

デザイン

日本IT風、簡潔、浅色、印刷対応など。

Prompt Template

良いPromptは、AIに判断基準と禁止事項を渡す

テーマ: AIツールでWeb版PPTを作る方法
目的: 部門内で、短時間に発表資料を作る手順を共有する
観客: 生産技術部のメンバー
言語: 日本語
ページ数: 10ページ以上
スタイル: 日本IT風、簡潔、浅色

必須要件:
- 1ページ1メッセージ
- HTML / CSS / JavaScriptを分離
- 全画面、翻頁、進捗、ページ番号、印刷PDFに対応
- データがない箇所は推測せず、[要確認] と書く
- 完成後に文字溢れと操作を確認する

Workflow

生成後は、人が確認しながら短い指示で磨き込む

1

素材を渡す

テーマ、目的、観客、制約、既存メモをPromptにまとめる。

2

初稿を生成

AIにHTML、CSS、JavaScript、READMEを作成させる。

3

ブラウザ確認

文字量、配置、操作、印刷表示を実際に見る。

4

差分修正

「第6頁を短く」「配色を薄く」など具体的に指示する。

Demo Output

成果物は、発表・修正・PDF化まで一つのフォルダで完結する

AI Web PPT
‹ ⛶ PDF ›

  • 前後ボタン、キーボード、全画面操作に対応
  • ページ番号と進捗バーで現在位置を把握
  • ブラウザの印刷機能でPDFとして保存

Quality Check

AI生成PPTは、公開前に4つの観点で確認する

内容

  • 事実と推測が混ざっていないか
  • 各ページの結論が明確か

視認性

  • 文字が多すぎないか
  • 投影時に読めるサイズか

操作

  • 翻頁、全画面、印刷が動くか
  • スマートフォン幅でも崩れないか

情報管理

  • 社内情報を外部に出していないか
  • 画像や引用の扱いに問題がないか
