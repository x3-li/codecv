# LLM性能テスト方針報告書

## 1. 目的

本報告書は、社内利用を想定してNvidia DGX Sparkサーバー上にデプロイしたオープンソースLLMについて、性能およびスループットを評価するためのテスト方針を整理することを目的とする。  
今回の評価では、GuideLLMを用いて、同時利用者数の増加に伴う応答性能、トークン処理性能、および遅延特性を定量的に把握する。

---

## 2. システム構成

### 2.1 ハードウェア構成

- サーバー名：Nvidia DGX Spark
- メモリ構成：CPU/GPU統一メモリ 128GB

### 2.2 ソフトウェア構成

- 推論サーバー：vLLM
- APIゲートウェイ：LiteLLM
- モデル起動方式：1回の起動につき1モデルのみ

### 2.3 テスト対象モデル

- gemma4-26B-A4B-it
- gemma4-31B-it

---

## 3. 性能テストの概要

### 3.1 使用ツール

性能テストには GuideLLM を使用する。  
GuideLLM 公式情報：<https://github.com/vllm-project/guidellm>

### 3.2 テスト観点

本テストでは、主に以下の観点を確認する。

- 同時実行数ごとのスループット特性
- 同時実行数ごとのリクエスト遅延特性
- 社内利用想定（最大20名程度）に対する実運用上の妥当性
- モデル間の性能差異
- 安定運用可能な同時実行数の目安

---

## 4. GuideLLM テスト方針

### 4.1 Benchmark Profile

今回のテストでは `--profile concurrent` を採用する。  

| `--profile` 値 | 説明                                    | `--rate`                    | `--rampup`                               |
| ------------- | ------------------------------------- | --------------------------- | ---------------------------------------- |
| `synchronous` | 同期・直列実行。リクエストを1件ずつ順番に実行する             | 使用不可                        | 未使用                                      |
| `throughput`  | 並列で継続的にリクエストを送り、サーバーの最大スループットを測る      | 同時リクエストストリーム数               | 最大スループットまで段階的に増やす時間（秒）                   |
| `concurrent`  | 固定数の並列リクエストを維持して実行する                  | 維持する同時リクエスト数。単一値または複数値を指定可能 | 初期リクエストを目標並列数まで分散して立ち上げる時間（秒）            |
| `constant`    | 1秒あたり一定レートで非同期リクエストを送信する              | 1秒あたりのリクエスト数。単一値または複数値を指定可能 | 0 から目標レートまで線形に増加させる時間（秒）                 |
| `poisson`     | 指定レート周辺でポアソン分布に従って変動しながら非同期リクエストを送信する | 最大非同期リクエスト数。単一値または複数値を指定可能  | 未使用                                      |
| `sweep`       | 最適な性能点を探すために、複数の戦略を順番に実行する            | sweep 内で実行する戦略数             | throughput と constant の各段階で使うランプアップ時間（秒） |


### 4.2 データ設定方針（--data）

`--data` では、入力トークン数と出力トークン数を設定する。  
社内利用を想定した一般的な対話・業務利用に近い負荷を再現するため、以下のような代表値を採用する。

#### 初期推奨値

- `prompt_tokens = 1024`
- `output_tokens = 512`

必要に応じて、以下のように複数パターンで補足測定を行ってもよい。

- 軽量リクエスト：`prompt_tokens=512, output_tokens=128`
- 標準リクエスト：`prompt_tokens=1024, output_tokens=1024`
- 高負荷リクエスト(Claude code)：`prompt_tokens=16384, output_tokens=1024`

### 4.3 実行条件

- モデルごとに個別に起動して測定する
- 各 concurrent 条件で同一設定を維持する
- 可能であればウォームアップ後に本計測を実施する
- 他ジョブの影響を避けるため、測定中はサーバー負荷をできるだけ固定する
