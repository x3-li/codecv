# 本番作業手順 概要まとめ

## ローカル LLM / AI Chat 環境構築

## 1. 作業目的

本番室内にローカル LLM 環境を構築し、各チームの作業者がブラウザから AI Chat 画面を利用できるようにする。

---

## 2. 全体概要

本作業では、以下の 3 台の物理マシンを使用する。

| マシン                   | 用途                                             |
| --------------------- | ---------------------------------------------- |
| Windows 物理マシン         | WSL2 / Ubuntu、LiteLLM、PostgreSQL、OpenWebUI を稼働 |
| DGX Spark GPU 物理マシン 1 | vLLM を起動し、AI Model API を提供                     |
| DGX Spark GPU 物理マシン 2 | vLLM を起動し、AI Model API を提供                     |

本番室はインターネット接続がない閉域環境である。
また、マシンを本番室へ搬入した後に持ち出す場合は初期化が必要となるため、搬入前に必要な設定、ソフトウェア導入、Docker Image ダウンロード、AI Model ダウンロード、設定ファイル作成を完了させておく。

作業は大きく以下の 2 フェーズに分ける。

1. 本番室搬入前作業
2. 本番室搬入後作業

---

# 3. 本番室搬入前作業

## 3.1 Windows 物理マシン

Windows 物理マシンでは、以下の準備を行う。

* Windows 初期設定
* 本番用ユーザー作成
* IP アドレス設定
* インターネット接続確認
* 必須ソフトウェアのインストール
* WSL2 の導入
* Ubuntu 24.04 のインストール
* Ubuntu 初期設定
* Docker / Docker Compose のインストール
* 必要な Docker Image の事前取得

  * LiteLLM
  * PostgreSQL
  * OpenWebUI
* Docker Compose 設定ファイルの作成
* LiteLLM 設定ファイルの作成

搬入前に、WSL Ubuntu 上で Docker が正常に利用できること、必要な Docker Image がすべて取得済みであることを確認する。

---

## 3.2 DGX Spark GPU 物理マシン 2 台

DGX Spark 2 台では、それぞれ以下の準備を行う。

* OS 初期設定
* 本番用ユーザー作成
* IP アドレス設定
* インターネット接続確認
* OS Update
* Docker / Docker Compose のインストール
* NVIDIA GPU 認識確認
* vLLM OpenAI 互換 API 用 Docker Image の事前取得
* AI Model の事前ダウンロード
* Docker Compose 設定ファイルの作成

搬入前に、`nvidia-smi` で GPU が正常に認識されること、vLLM 用 Docker Image と AI Model がローカルに存在することを確認する。

---

# 4. 本番室搬入後作業

## 4.1 機器接続・起動

本番室内で以下の作業を行う。

* Windows 物理マシンの電源・LAN ケーブル接続
* DGX Spark 1 の電源・LAN ケーブル接続
* DGX Spark 2 の電源・LAN ケーブル接続
* 3 台のマシンを起動

---

## 4.2 Windows 物理マシン設定

Windows にログインし、以下を確認する。

* IPv4 アドレス設定
* DGX Spark 1 への疎通確認
* DGX Spark 2 への疎通確認

確認例：

```powershell
ping <DGX1_IP>
ping <DGX2_IP>
```

---

## 4.3 DGX Spark 上の vLLM 起動

Windows 物理マシンから SSH で DGX Spark 2 台へ接続する。

```powershell
ssh <DGX_USER>@<DGX_IP>
```

各 DGX Spark 上で vLLM を起動する。

```bash
cd <作業ディレクトリ>/vllm
docker compose up -d
```

起動確認を行う。

```bash
docker ps
docker logs vllm
```

vLLM API の確認を行う。

```bash
curl http://<DGX_IP>:8000/v1/models
```

モデル情報が返却されれば、vLLM 起動確認は完了。

---

## 4.4 Windows WSL Ubuntu 上の LiteLLM 起動

Windows から WSL Ubuntu に入り、作業ディレクトリへ移動する。

```powershell
wsl -d Ubuntu-24.04
```

```bash
cd <作業ディレクトリ>/local-llm
```

まず PostgreSQL と LiteLLM を起動する。

```bash
docker compose up -d postgres litellm
```

LiteLLM の起動状態を確認する。

```bash
docker ps
docker logs litellm
```

LiteLLM のモデル一覧確認を行う。

```bash
curl http://localhost:4000/v1/models \
  -H "Authorization: Bearer <LITELLM_API_KEY>"
```

DGX Spark 1、DGX Spark 2 の vLLM モデルが表示されることを確認する。

---

## 4.5 OpenWebUI 起動・接続確認

OpenWebUI を起動する。

```bash
docker compose up -d openwebui
```

ブラウザから以下 URL にアクセスする。

```text
http://<WINDOWS_IP>:8080
```

OpenWebUI 画面が表示されることを確認する。

OpenWebUI から LiteLLM へ接続し、以下を確認する。

* モデル一覧が表示されること
* DGX Spark 1 のモデルで会話できること
* DGX Spark 2 のモデルで会話できること
* AI Chat 画面が正常に利用できること

---

## 4.6 本番利用設定

OpenWebUI で本番利用に必要な設定を行う。

* 管理者ユーザー作成
* 一般ユーザー利用方針の設定
* モデル表示名の調整
* デフォルトモデル設定
* アクセス権限確認
* ログ保存方針の確認
* 本番利用 URL の確定

本番利用 URL：

```text
http://<WINDOWS_IP>:8080
```

---

## 4.7 本番室 PC からの利用確認

本番室 PC のブラウザから AI Chat 画面へアクセスする。

```text
http://<WINDOWS_IP>:8080
```

以下を確認する。

* OpenWebUI 画面が表示されること
* ログインできること
* AI Model を選択できること
* 質問を送信できること
* AI から回答が返ってくること
* 各 Team の作業者が利用できること

---

# 5. 完了条件

以下がすべて確認できれば、作業完了とする。

* Windows 物理マシンが正常に起動している
* DGX Spark 2 台が正常に起動している
* Windows と DGX Spark 2 台のネットワーク疎通が取れている
* DGX Spark 2 台で vLLM が正常に起動している
* Windows WSL Ubuntu 上で PostgreSQL、LiteLLM、OpenWebUI が正常に起動している
* LiteLLM から 2 台の vLLM モデルへ接続できる
* OpenWebUI から AI Chat が利用できる
* 本番室 PC から AI Chat 画面へアクセスできる

---

# 6. 障害時の主な確認ポイント

## ネットワーク疎通不可の場合

* IP アドレスが正しいか
* Subnet Mask が正しいか
* LAN ケーブルが接続されているか
* 対象マシンが起動しているか
* Firewall により通信が遮断されていないか

## vLLM 起動不可の場合

* GPU が認識されているか
* AI Model のパスが正しいか
* Docker Image が存在するか
* 8000 番ポートが使用されていないか
* Docker Compose 設定に誤りがないか

## LiteLLM 接続不可の場合

* vLLM が起動しているか
* DGX Spark の IP が正しいか
* LiteLLM 設定ファイルの `api_base` が正しいか
* Windows / WSL から DGX Spark へ通信できるか

## OpenWebUI 画面表示不可の場合

* OpenWebUI コンテナが起動しているか
* 8080 番ポートが利用可能か
* Windows IP が正しいか
* ブラウザのアクセス URL が正しいか

本作業の重要ポイントは、本番室がインターネット非接続環境であるため、搬入前に必要な準備をすべて完了させることである。
搬入後は、ネットワーク接続、vLLM 起動、LiteLLM 起動、OpenWebUI 起動、AI Chat 動作確認の順番で作業を進める。
最終的に、本番室 PC からブラウザ経由で AI Chat 画面を利用できることを確認し、作業完了とする。
